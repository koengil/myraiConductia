## Strongest findings

1. **Recovery APIs exist in Ignatious.** Conversation lookup/read and durable run replay support reopening a popup, subject to persistence configuration. Closing a popup is different from calling the conversation-close API, which removes it from current-conversation lookup. [Operations](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/control-plane-api/src/bench-operations.ts:136).
2. **Authoring currently saves through model tools.** Draft prose does not itself register a skill, but a successful `create_skill` call immediately creates an enabled, runnable library entry, normally visible on the current deal only. There is no public structured draft, draft-artifact selection, or explicit Save endpoint. [Tool](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill-tool.ts:61), [implementation](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill.ts:211), [complete public operation table](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/control-plane-api/src/bench-operations.ts:92).
3. **New direct package uploads are firm-wide.** Chat creation narrows visibility in a second synchronous write after staging. Replacing an existing skill preserves its visibility. This is not an atomic unpublished-draft mechanism. [Creation](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill.ts:236), [upload defaults](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/skill-store.ts:1281).
4. **No project-step creation or exact-once Save transaction exists here.** The rail belongs to Conductia; the contract exposes its read. Skill creation attaches to an already selected step. The rail schema has neither a skill execution binding nor a single-input definition. [Rail ownership/schema](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/conductia-contract/src/process.ts:4), [rail read operation](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/conductia-contract/src/operations.ts:228).
5. **The skill identifier is its mutable folder name.** A subsequent bench message can invoke `/<name>`; execution has no requested version/hash field. Arbitrary new bench skills are not registered control-plane run agents. [Chat schema](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/control-plane-api/src/bench-schemas.ts:158), [creation instructions](/Users/cwillian/Documents/personal/learning/ignatious/platform/claude-skills/skills/create-skill/SKILL.md:65), [control-plane names](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/conductia-contract/src/run.ts:116).

## Internal authoring tools and the Save boundary

`create_skill` takes `{name,skillMdText,referenceFiles?}`. References are a string-to-string map restricted to safe paths below references/; this authoring function rejects scripts/ entries. Tag, lead and attribution come from the conversation's scope, not model arguments. The result is `{created:true,conversationId,skillName,version,tag,visibility}`. [Input/result wrapper](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill-tool.ts:61), [allowed files](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill.ts:70).

The tool checks that a completed earlier conversation turn ran the create-skill skill and that selection is non-null. The skill's prose instructs the model to show the full file and wait for the banker, but the executable gate does not validate an approval token, approved content hash, Save event, or exact accepted draft. Consequently, “generation stays unpublished until application Save” is not an enforced API invariant. A draft-only conversation can remain prose, but the normal tool-enabled chat can save once its history gate is satisfied. [Gate](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill-tool.ts:106), [history wiring](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/turn-agent.ts:398), [prompt instruction](/Users/cwillian/Documents/personal/learning/ignatious/platform/claude-skills/skills/create-skill/SKILL.md:57).

Creation refuses existing or reserved seed names, validates the new SKILL.md, builds a ZIP, calls stageSkillUpload with replaces:null, then writes `{kind:"deals",leadIds:[leadId]}`. Normal completion is enabled and deal-only, not firm-wide. However, the intermediate staging write is firm-wide; the later scope write has no rollback transaction. Both are synchronous once staging begins, so this is not evidence of a same-process event-loop exposure window. Process failure, another process reading the mount, or write failure remain relevant failure scenarios. [Creation sequence](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill.ts:141), [stage/scope boundary](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill.ts:211), [enabled default](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/skill-store.ts:1295).

Iteration uses internal `commit_skill_version`, with skillName, skillMdText, description and optional referenceFiles. It requires prior skillbuilder history and immediately stages a new live version; it is not a public commit endpoint or an unpublished draft store. Replacing bytes preserves current visibility, so the tool description's unconditional “firm-wide” wording is broader than current store behavior. [Tool schema/gate](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/commit-skill-version-tool.ts:57), [preserved visibility](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/skill-store.ts:1281).

Neither authoring function creates a Conductia step or runs the new skill. The creation skill tells the banker it mounts on the next message and offers `/<name>`. There is no saved structured single-input contract. The runtime-authoring reference is [create-skill/references/runtime.md](/Users/cwillian/Documents/personal/learning/ignatious/platform/claude-skills/skills/create-skill/references/runtime.md:1); its allowed-capability prose should be checked against current tool implementation, not treated as a public API schema.

## Recovery, persistence, concurrency and retry semantics

- **Completed history:** transcript.json stores model messages, is written at turn end using temporary-file rename, and retains the last 400 messages. Missing/corrupt transcript reads as empty. Metadata is written on the first turn, allowing discovery even before completed history exists. [Transcript](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/transcript.ts:44), [metadata timing](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/session.ts:359), [turn tail](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/turn-tail.ts:125).
- **Disconnect:** the SSE generator drains to completion after the client leaves. A popup can disappear while the server continues writing history and spend. The close API writes a separate closed marker, excludes lookup, and deletes nothing. It is not a cancellation API. [Stream loop](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/sse.ts:118), [close](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/server.ts:883).
- **Rejoin:** requires SKILL_BENCH_DURABLE enabled (default true) and live model mode. Redis provides cross-process replay; without Redis it is in-memory only. Completed buffers have a ten-minute cleanup timer; orphan buffers use six-hour TTLs, also subject to eviction/cache failures. Transcript GET remains the source after replay expires. [Condition](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/session.ts:702), [config default](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/config.ts:643), [cache modes](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/run-cache.ts:9), [retention](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/run-cache.ts:64).
- **Process recovery:** Postgres snapshots require SKILL_BENCH_DATABASE_URL; replay storage alone does not resume execution. Current recovery accounts for a Mastra tool-rehydration limitation by recording the interrupted run and issuing a new ordinary runTurn with RESUME_MESSAGE and resumeOf. This may make additional model/tool calls and spend; it is not a free reconnect or exact-once side-effect guarantee. The caller token is persisted in the snapshot scope and reused; real token expiry during recovery remains an integration question. [Snapshots](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/snapshots.ts:43), [recovery explanation](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/recovery.ts:9), [continuation call](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/recovery.ts:549), [credential lifetime](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/turn-scope.ts:26).
- **Concurrent messages:** no per-conversation lock, active-turn admission check, queue, or request idempotency key was found on the inspected POST/server/session path. Each turn reads history and later replaces it; the active-run record is one cache value per conversation, overwritten with set and removed with delete. **Inference, not reproduced:** overlapping turns can lose transcript updates or misreport the active run; a shared temporary transcript filename is another race surface. Atomic file rename prevents partial JSON, not lost updates. [POST dispatch](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/server.ts:529), [history read](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/session.ts:550), [history write](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/transcript.ts:74), [active set](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/active-turn.ts:85), [active delete](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/active-turn.ts:136).
- **Concurrent new chats:** no-ID messages each mint a UUID. Lookup scans directories and returns the newest unclosed matching metadata record, rather than enforcing a unique active conversation. Concurrent first messages can therefore produce multiple conversations for one address. [UUID creation](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/session.ts:359), [lookup algorithm](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/current.ts:79).
- **Duplicate creation:** sequential creation of the same name refuses and preserves the first skill. The final synchronous staging function repeats the collision check, protecting normal same-process duplicate attempts even though initial preparation is asynchronous. It has no cross-process lock or compare-and-set reservation. No idempotent receipt lookup or content-hash equality recovery exists in this path. A retry after success but response loss gets “already exists,” not the original success. Explicit replacement or omitted replaces can stage another version on retry. Cross-process races remain untested. [Collision checks](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill.ts:151), [final guard](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/skill-store.ts:1153), [synchronous stage](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/skill-store.ts:1201), [duplicate test](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/create-skill.test.ts:138).

## Identity, deal/project isolation and execution identity

The shared inbound key authenticates the calling integration, returning 401 for missing/wrong keys. Bench identity extraction merely decodes the userEmail JWT claim; it verifies neither signature nor expiry. TenantId and leadId arrive independently in the request and are compared with stored conversation metadata, not with an authenticated user-membership record. User attribution is not a read/write authorization boundary. Legacy conversations lacking metadata bypass the scope comparison. [API-key implementation](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/http-envelope/src/api-key.ts:58), [claim decoding](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/token.ts:39), [scope comparison](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/meta.ts:187), [legacy behavior](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/meta.ts:208).

Conductia tool clients are constructed for the requested tenant/lead, and the model cannot supply another lead to those tools. The bearer token is forwarded. A requested Conductia base URL must pass the configured allowlist before streaming, but it is a per-turn choice, not an immutable field of the conversation address. Actual Conductia must enforce its own permissions. [Scoped client](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/turn-agent.ts:187), [target validation](/Users/cwillian/Documents/personal/learning/ignatious/platform/apps/skill-bench/src/server.ts:436), [request target](/Users/cwillian/Documents/personal/learning/ignatious/platform/packages/control-plane-api/src/bench-schemas.ts:164).

Skills use one shared name space under skillsRoot. Visibility is firm or a list of lead IDs, with hiddenOn taking precedence; it contains no tenant/project/user ID. A step selection mounts its tagged skills plus always utilities; it is not an exact skill/version selector. /name is a message convention, and the next turn re-reads currently enabled/visible packages. ready.skills records name and version but the request cannot pin either version or hash.
