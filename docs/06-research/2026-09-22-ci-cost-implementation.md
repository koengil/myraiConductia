# CI cost implementation, September 22, 2026

## Scope and decisions

Implemented on feature branch `reduce-github-actions-cost`, based on current `origin/develop` at `c05d1306d4e8a9c3d442703ec064730d00ee0126` (fetched September 22). The earlier analysis used `9a8ec08`; the subsequent workflow change passes `DATABASE_URL` to integration tests and is preserved. The two original research files were copied byte-for-byte from the original checkout, which was not modified.

- Security audits the lockfile without installing dependencies or restoring/saving an npm download cache. Production still blocks at moderate severity; full-tree findings remain visibility-only. Other workflow installs use `--no-audit`, including live E2E and release preflight; preflight retains `--ignore-scripts` and its environment approval.
- Added complete-history classification and explicit gates inside the three existing expensive jobs. All four required names remain identical, without top-level path filters or branch ruleset changes. Security runs on every event. A docs-only execution still allocates three short gate runners plus classification and security; savings are eliminated work, not zero-cost runs.
- Eligible paths: `README.md`, `docs/README.md`, and direct `.md` children of `docs/{00-vision,01-business,02-product,03-engineering,04-operations,04-brand,05-growth,06-research,07-decisions}`. Nested files, other root Markdown, fixtures, skills, design assets, workflow/config/dependency/source changes run full CI.
- PR classification uses merge-base to PR head, including earlier commits. Push classification uses the full before/after range. Rename detection is disabled so both old and new paths count. Empty ranges, shallow or missing history, malformed events, unsupported events, forced/non-ancestor pushes and diff errors select full CI. Failed/cancelled/skipped detection jobs or malformed outputs fail the existing required jobs before checkout/install.
- Post-merge `develop` and `main` triggers, release preflight, cancellation, existing npm caches, test coverage, independent database jobs and distinct Next compile-time environments are preserved. Failure reporting runs only when the E2E gate admitted the suite.
- Both CI Supabase starts exclude `studio,postgres-meta,edge-runtime,realtime,logflare,vector`, after full validation with CLI 2.116.0. Database, gateway, Auth, REST, Storage and mail stay. The tracked local-development configuration and both resets remain unchanged.

## Cost interpretation and remaining opportunities

A full CI execution now has three dependency installs instead of four, plus a classification job and regression-test overhead. Eligible documentation executions avoid all three installs, both Supabase startups/resets, browser installation/tests, and both builds; the security audit and short gate jobs remain. Per-job minute rounding, runner startup, checkout cost, cache transfers and shared allowance determine actual savings.

Before adopting runner changes, collect repeated hosted x64/ARM/slim samples using the same SHA and job inputs, measuring rounded billable job time and failure rates. Slim is unsuitable for Docker/Supabase jobs. Shared database setup must include a reset between integration and E2E and preserve both independent required outcomes. Build caching must retain separate verification/hermetic namespaces and compare transfer overhead against warm-build benefit; their build artifacts are not interchangeable. No dollar savings are claimed.
