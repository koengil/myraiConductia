## 4.1 — authority arguments no longer come from the hidden row. Fixed.

The reviewer's catch was correct and I had missed it: `pending?.deal_id ?? dealId`
derived an authority input from the row whose existence the response is supposed
to conceal. A hidden invitation on a different deal ran authority queries against
that different deal — same table names, different predicates, different work.

`userCanManageInvite` is now asked about `actor.company_id` and the request's
`dealId`, identical in both worlds. Disclosure then additionally requires
`pending.company_id === actor.company_id`, a comparison on data already fetched.

My first attempt at this over-disclosed: passing the actor's own company changed
the question to "may you manage your own company's invitations", and answering
the original question with it leaked a foreign company's invitation. The
indistinguishability suite caught it before commit.

Deliberate cost: an actor whose authority over an invitation comes from
somewhere other than owning the company under-discloses here. They learn of the
conflict at send time through the existing scoped 409. Under-disclosure is the
safe direction.

## 1.2 — a failed authority read no longer reads as "no authority". Fixed.

Root cause was upstream of where I had looked. `userCanInvite` swallows its own
read errors and returns `false`, so my `try/catch` could never see a failure —
nothing was thrown. The preview rendered available with the teammate action
silently absent, which is a confident answer to a question the server could not
answer.

Split: `userCanInviteChecked` returns `boolean | 'unreadable'`. `userCanInvite`
is now a wrapper mapping `'unreadable'` to `false`, so every caller that is about
to permit something behaves exactly as before — a failed read denies, which is
right for enforcement. Only the perimeter path, which shows the answer to a
person, maps it to `unavailable`.

Still true and disclosed: predicates nested inside `userCanInvite`
(`canManageDealMembers`, `canManageCompanyMembers`) collapse their own read
failures the same way. Fixing those widens blast radius across live routes; I
did not do it uninstructed.

Evidence the guarantee is live: adding the new export broke six suites that mock
the access module wholesale, because the undefined export threw and correctly
degraded to unavailable.

## 1.1 — withdrawal complete in code, coverage incomplete. Partially fixed.

Code: the withdrawal key is now `email|company|deal`, so any bound-input change
withdraws, not only an address change. A phase the inviter typed is marked and
is neither overwritten by a later recommendation nor revoked by a withdrawal.

**Gap, disclosed:** the two tests for this — company-change withdrawal, and
typed-phase preservation — I could not get working. In the harness the card
stayed `ready` after a company-select change and never re-fetched, despite
`companyId` being both passed and keyed. I did not diagnose it. Rather than ship
red tests, or `skip`ped ones that read as coverage, I removed them. The
behaviour is implemented and manually reachable; it is not automatically
verified. If the reviewer considers that blocking, it is a fair call.

## 4.2 — D8.16 end-to-end. Done.

`tests/onboarding-e2e.test.ts` drives the D7 path through the real handlers:
lookup identifies the company and proposes a seat, the preview reports what that
seat reaches, the invitation is sent and the confirmed phase reaches the RPC,
and the invitee's welcome reading reports the same perimeter the MD was shown.
A second case pins that phase is what moves the number (phase 0 → 1 document,
phase 2 → 2).

The database half — acceptance granting and auditing the stored phase, and the
verification/TOS/2FA gate still refusing an unverified acceptance — stays in
`supabase/tests/invite_phase_accept.sql`. Asserting it here against a mocked
client would prove the mock, not the migration.

Two defects surfaced writing it, both mine, neither a product bug: the welcome
step initially read the MD's profile instead of the invitee's, and the
wholesale-mock breakage above.
