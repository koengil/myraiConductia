# infra/discovery-worker

OpenTofu for the deal-discovery worker in Ignatious's dedicated AWS account (#344). `bootstrap/` creates the state bucket once; the root module holds the network, keys, image repository, roles (the task, execution and MFA-guarded `deploy` roles), secret containers, logs, the trail, egress and runtime detection (flow logs, Resolver query logs, the DNS Firewall, GuardDuty), the alerts to the owner and the CCO and the alarms, and, once an image digest is set, the five task families and two services at desired count 0. It is applied only by the owner, in the order of [the runbook](../../docs/04-operations/discovery-worker-aws-runbook.md); start with it, not here. Nothing in CI or on a developer machine plans or applies it against an account: `scripts/infra/validate.sh` runs `tofu fmt -check`, `init -backend=false`, `validate` and `tofu test` with a mock provider, offline.
